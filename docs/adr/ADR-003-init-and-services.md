# ADR-003: نظام الـ init والخدمات لسديم OS

- **الحالة:** مقبول مبدئياً — مرحلة v0.2 منفَّذة فعلاً ومُختبَرة في CI؛ التصميم الموسع (مرحلة 3) مبيّن أدناه.
- **التاريخ:** 2026-11-11
- **مرتبط بـ:** ADR-001 (init خاص بدون systemd مبدئياً)، ADR-002 (حزمة العرض).

## 1. السياق

الهدف: نظام init خاص بسديم، خفيف جداً على 4GB/SMR، بدون تعقيد systemd، مع مسار نمو واضح.
المُنفَّذ فعلاً حتى الآن (دليل: `sadim/initramfs/init` v0.2 + `sadim/initramfs/rootfs/etc/inittab`):

## 2. القرار المنفَّذ v0.2 (init = سكربت سديم + busybox init)

```
[نواة] → /init (سكربت سديم)
        1. mount proc/sys/devtmpfs
        2. hostname sadim + شعار الهوية
        3. طباعة وسم SADIM-BOOT-OK (بوابة الاختبارات)
        4. وضع CI (SADIM_CI=1): إقلاع نظيف يُنهي QEMU
        5. الوضع العادي: exec /sbin/init (busybox init)
              /etc/inittab:
                sysinit → /etc/rcS (تجهيز var/tmp + سجل الإقلاع)
                tty1  → getty + autologin (Live فقط — موثق)
                ttyS0 → getty تسلسلي (تتبّع/CI)
                ctrlaltdel → reboot
```

**لماذا busybox init وليس systemd؟** يكفي للتشغيل Live والخدمات المبسطة؛ صفر تعقيد إضافي على SMR؛
وكل سلوك مرئي في ملفين (init + inittab) قابلين للمراجعة البشرية. systemd = ~40MB+ إضافية ووضعية تشغيل
ثقيلة — قرار معلن، لا قياسات خيالية (قياس الاستهلاك الحقيقي في المرحلة 7).

## 3. التصميم الموسع للمرحلة 3 (المرحلة القادمة)

| المكوّن | القرار | الشكل |
|---|---|---|
| المستخدمون/الصلاحيات | `login` حقيقي بكلمات مرور + إلغاء autologin في النسخ المثبتة | /etc/passwd + shadow (busybox) |
| الخدمات | سكربتات S## في /etc/init.d عبر rcS (شبكة → تسجيل → خدمات سديم) | init scripts بسيطة قابلة للمراجعة |
| التسجيل | سجل إقلاع في /var/log/boot.log + سجلات dmesg | بلا syslog خادم في Live |
| إدارة العمليات | as-is (النواة) + حسابات cgroup لاحقاً إن لزم | — |
| الإعدادات | /etc/sadim/*.conf ملفات نصية + سكربتات | بلا مركز تسويق ثقيل |
| الطاقة | poweroff/reboot عبر busybox + ACPI (مضمّن في fragment v0.2) | — |

## 4. حدود معلنة (لا تُخفى)

- v0.2 autologin root مقصود للـ Live فقط — يُزال عند التثبيت الحقيقي (مرحلة ثنائية الإقلاع لاحقاً بموافقة المالك).
- لا إدارة جلسات متعددة مستخدمين بعد (تأتي مع سطح المكتب Phase 4).
- كل ادعاءات الأداء مؤجلة للمرحلة 7 بقياسات فعلية.

## 5. التحقق

- بوابة النواة: `-kernel` + SADIM_CI=1 (workflow `kernel-boot.yml`).
- بوابة ISO: مسار إقلاع حقيقي SeaBIOS→isolinux→init (workflow `live-iso.yml`).
- كلاهما: وسم `SADIM-BOOT-OK` ×3 تشغيلات متتالية.
